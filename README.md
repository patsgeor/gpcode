# gpcode.gr

Στατικός εταιρικός ιστότοπος για το software studio **gpcode**.
22 σελίδες, HTML5 · CSS3 · Bootstrap 5 · vanilla JavaScript.

Καμία βάση δεδομένων, κανένα CMS, κανένα framework στο frontend.
Το Node χρησιμοποιείται **μόνο τοπικά κατά το build** — το αποτέλεσμα που
ανεβαίνει είναι καθαρά στατικά αρχεία.

---

## Γρήγορη εκκίνηση

```bash
npm install
npm run setup:assets    # μία φορά: sprite, favicons, OG image, γραμματοσειρές
npm run build           # παραγωγή + έλεγχοι ποιότητας
npm run serve           # τοπική προεπισκόπηση στο http://localhost:8099
```

## Εντολές

| Εντολή | Τι κάνει |
|---|---|
| `npm run dev` | Build ανάπτυξης — ξεχωριστά `style.css` και `*.js`, ευανάγνωστα |
| `npm run build` | Build παραγωγής + optimize + έλεγχος συνδέσμων |
| `npm run dist` | Τα παραπάνω και συγκέντρωση σε `dist/` έτοιμο για ανέβασμα |
| `npm run check` | Μόνο επαλήθευση εσωτερικών συνδέσμων και αγκυρών |
| `npm run serve` | Τοπικός διακομιστής στο 8099 |
| `npm run setup:assets` | Ξαναφτιάχνει sprite, favicons, OG image, αντιγράφει fonts |

Για ανέβασμα ανεβάστε **το περιεχόμενο του `dist/`** στη ρίζα του χώρου
φιλοξενίας. Το `dist.js` αρνείται να ολοκληρώσει αν το HTML δείχνει ακόμη σε
assets ανάπτυξης, ώστε να μη δημοσιευτεί ποτέ κατά λάθος dev build.

## Πού αλλάζω τι

### Περιεχόμενο και στοιχεία επικοινωνίας → `js/data.js`

Ένα αρχείο, μία πηγή αλήθειας. Τηλέφωνο, email, ΑΦΜ, υπηρεσίες, τεχνολογίες,
δεσμεύσεις, νούμερα, διαδικασία, FAQ και μεταδεδομένα άρθρων ζουν όλα εκεί.
Αλλάζετε μία τιμή, τρέχετε `npm run build`, ενημερώνονται όλες οι σελίδες.

Το ίδιο αρχείο διαβάζεται και από τον browser (`window.SITE_DATA`) και από τα
build scripts (`require`) — μία γραμμή στο τέλος κάνει τη διπλή εξαγωγή.

### Εμφάνιση → `css/style.css`

25 αριθμημένες ενότητες. Τα design tokens βρίσκονται στην ενότητα 02 και τα
`--bs-*` του Bootstrap δείχνουν σε αυτά, οπότε τα components του Bootstrap
κληρονομούν την ταυτότητα χωρίς overrides.

Ο κατακόρυφος ρυθμός είναι σκόπιμα **πυκνός** (`--section-y`, `--card-pad`).
Η premium αίσθηση προκύπτει από τυπογραφική ιεραρχία, σκιές και gradients —
όχι από κενό χώρο.

#### Σκούρο θέμα

Το site είναι **dark-first**. Η ιεραρχία επιφανειών, από τη βαθύτερη προς
την πιο ανυψωμένη:

| Token | Χρήση |
|---|---|
| `--bg-footer` `#04070E` | footer, το βαθύτερο σημείο |
| `--bg-body` `#070B14` | βάση σελίδας |
| `--bg-subtle` `#0B1220` | εναλλασσόμενες ενότητες |
| `--bg-surface` `#101A2C` | κάρτες και πλαίσια |
| `--bg-elevated` `#16223A` | hover και ένθετα στοιχεία |

**Δύο παγίδες που λύθηκαν και αξίζει να μη ξαναγίνουν:**

1. Το `#0B5ED7` του αρχικού brief δίνει μόλις **3.1:1** σε σκούρο φόντο.
   Παραμένει ως γέμισμα κουμπιών (λευκό από πάνω: 5.2–6.7:1) αλλά ως χρώμα
   κειμένου ή συνδέσμου χρησιμοποιείται το `--brand-primary` `#60A5FA`.
   Αντίστροφα, το teal `#14B8A6` που ήταν ανεπαρκές σε λευκό φόντο, εδώ
   δίνει 7.9:1 και είναι πλήρως χρησιμοποιήσιμο.

2. Το Bootstrap 5.3 παράγει χρώματα από μεταβλητές όπως
   `--bs-emphasis-color-rgb`, με προεπιλογές φτιαγμένες για ανοιχτό θέμα.
   Αν μείνουν ως έχουν, το ενεργό `.nav-link` βγαίνει **μαύρο σε μαύρο**.
   Οι μεταβλητές αυτές δείχνουν πλέον στα δικά μας tokens (`:root` και
   `.site-header .navbar`) — λύση από τα variables, όχι με specificity war
   που θα έσπαγε σε αναβάθμιση του Bootstrap.

Κάθε τιμή χρώματος στην ενότητα 02 συνοδεύεται από τον μετρημένο λόγο
αντίθεσης. Τα `--text-*` ελέγχονται πάντα στην **πιο φωτεινή** επιφάνεια
(`--bg-elevated`), όχι μόνο στη βάση.

#### Υφές και εικόνες

- `images/pattern-binary.svg` — δυαδικά ψηφία, παράγεται από το
  `setup-assets.js`. Στο `body::before` σε opacity `.045`, πυκνότερα στο hero.
- `images/pattern-circuit.svg` — γραμμές κυκλώματος, στα page heroes και στη
  σκούρα μπάντα των νούμερων.
- `images/green_code.webp` — φωτογραφία κώδικα ως στρώση στο hero. Φορτώνεται
  από CSS και **όχι** ως `<img>`, ώστε να μη διεκδικεί τη θέση του LCP· ένα
  `hue-rotate(28deg)` τη γέρνει από το πράσινο προς το κυανό της μάρκας.

Οι υπόλοιπες φωτογραφίες μπαίνουν με το `mediaFrame()` του
`components.js`, πάντα με ρητά `width`/`height` (μηδέν CLS) και `lazy`.

### Δομή σελίδων → `build/`

Μια σελίδα είναι ένα απλό αντικείμενο JavaScript· το `layout()` το μετατρέπει
σε HTML. Το `<head>`, το navbar, το footer και το cookie banner γράφονται
**μία φορά**.

```
build/
├── generate.js          παράγει τα .html + sitemap/robots/manifest + έλεγχοι
├── optimize.js          purge + concat + minify
├── check-links.js       επαληθεύει κάθε εσωτερικό href/src και κάθε άγκυρα
├── dist.js              συγκεντρώνει τον φάκελο ανεβάσματος
├── setup-assets.js      sprite, favicons, OG image, αντιγραφή fonts
├── pages-main.js        αρχική, σχετικά, υπηρεσίες (hub), έργα
├── pages-services.js    οι 7 σελίδες υπηρεσιών
├── pages-secondary.js   FAQ, επικοινωνία, νομικά, 404
├── pages-blog.js        ευρετήριο + τα σώματα των άρθρων
└── templates/
    ├── layout.js        το κέλυφος, το NAV, το footer, το @graph JSON-LD
    └── components.js    επαναχρησιμοποιήσιμα κομμάτια + κόμβοι schema
```

### Προσθήκη νέας υπηρεσίας

1. Εγγραφή στο `data.services`
2. Συνάρτηση σώματος στο `build/pages-services.js` και προσθήκη στο `all()`
3. `npm run build`

Το nav dropdown, το footer, η σελίδα `services.html`, οι κάρτες της αρχικής,
το sitemap και το `ItemList` schema ενημερώνονται μόνα τους.

### Πακέτα και τιμές → `data.packages`

Τα τέσσερα πακέτα κατασκευής ιστοσελίδων (200€ / 400€ / 800€ / 2.500€)
ορίζονται σε ένα σημείο και εμφανίζονται στη σελίδα
`services/web-development.html`.

⚠️ **Οι τιμές αναφέρονται και στο άρθρο** `poso-kostizei-mia-istoselida` και
**στην απάντηση FAQ** `kostos`. Αν αλλάξετε ποσό στο `data.packages`,
ενημερώστε και τα δύο — δύο διαφορετικές τιμές στο ίδιο site κοστίζουν
περισσότερο σε αξιοπιστία από καμία τιμή.

### Σελίδες-δείγματα → `examples/`

Τέσσερις σελίδες πλασματικών επιχειρήσεων (ιατρείο και συνεργείο, σε απλή
και Pro έκδοση) που δείχνουν στον πελάτη τι ακριβώς προσθέτουν τα επιπλέον
200€. Το εταιρικό πακέτο δείχνει σε πραγματικό εξωτερικό site.

Ζουν έξω από το σύστημα του gpcode:

- Δικό τους αυτόνομο `css/demo.css` — ανοιχτό θέμα, δικό τους χρώμα τόνου
  ανά κλάδο. Ένα δείγμα που μοιάζει με το site του κατασκευαστή δεν δείχνει
  τίποτα στον πελάτη.
- Δικό τους `build/templates/demo-layout.js`, όχι το `layout()`.
- Εξαιρούνται από το PurgeCSS content των κανονικών σελίδων, ώστε να μην
  κρατούν άσκοπα κανόνες Bootstrap στο `app.min.css`.

**Τρεις κανόνες που επιβάλλει το build** και θα αποτύχει αν παραβιαστούν:

1. Μόνιμη ορατή μπάρα «ΔΕΙΓΜΑ» που δηλώνει ότι η επιχείρηση είναι πλασματική
   και τα στοιχεία επικοινωνίας ανύπαρκτα.
2. `noindex, nofollow` — δεν πρέπει ποτέ να ευρετηριαστούν ως πραγματικές
   επιχειρήσεις.
3. **Κανένα structured data.** Δεν δημοσιεύουμε schema πλασματικής
   επιχείρησης, ούτε ως δείγμα.

Τα τηλέφωνα είναι σκόπιμα μη υπαρκτά (`210 000 00xx`) και η φόρμα στο Pro
δείγμα είναι ανενεργή — δεν συλλέγουμε δεδομένα από σελίδα επίδειξης.

### Προσθήκη άρθρου

1. Εγγραφή στο `data.posts`
2. Σώμα στο `BODIES` του `build/pages-blog.js` (τα `<h2 id="…">` παράγουν
   αυτόματα τον πίνακα περιεχομένων)
3. `npm run build`

## Έλεγχοι ποιότητας

Το `generate.js` τερματίζει με κωδικό ≠0 και **μπλοκάρει το build** αν:

- υπάρχει διπλότυπο `<title>` ή `<meta description>`
- μια περιγραφή είναι εκτός 70–165 χαρακτήρων
- μια σελίδα δεν έχει ακριβώς ένα `<h1>`
- κάποιο JSON-LD δεν είναι έγκυρο
- ο ίδιος κόμβος `@id` ορίζεται πλήρως σε δύο σελίδες
- η ίδια ερώτηση FAQ εμφανίζεται σε δύο `FAQPage`

Το `check-links.js` μπλοκάρει αν υπάρχει σπασμένος εσωτερικός σύνδεσμος ή
άγκυρα προς `id` που δεν υπάρχει.

## Τεχνικές αποφάσεις

**Γραμματοσειρές.** Inter, self-hosted, χωρισμένη σε ελληνικό και λατινικό
subset με `unicode-range`. Το ελληνικό είναι ~8KB ανά βάρος και κατεβαίνει
πάντα· το λατινικό μόνο όταν εμφανιστεί λατινικός χαρακτήρας ή ψηφίο.
Μηδέν αιτήματα σε CDN — και για ταχύτητα και για GDPR.

**Εικονίδια.** Το `icons/sprite.svg` περιέχει 73 σύμβολα, αλλά κάθε σελίδα
ενσωματώνει μόνο όσα πραγματικά χρησιμοποιεί (τυπικά 25–30). Μηδέν επιπλέον
αιτήματα, μηδέν icon font. Το ίδιο το sprite δεν ανεβαίνει στην παραγωγή.

**CSS.** Το Bootstrap περνά από PurgeCSS (227KB → ~58KB) και συγχωνεύεται με
το `style.css` σε ένα `app.min.css` — ένα render-blocking αίτημα. Το
`style.css` μπαίνει δεύτερο ώστε να κερδίζει στο cascade.

**JavaScript.** ~8.5KB συνολικά, όλα με `defer`. Το `nav.js` (1.2KB)
αντικαθιστά το bundle του Bootstrap για τις δύο μόνο συμπεριφορές που
χρειάζονται. Τα FAQ accordions είναι native `<details>` — μηδέν JS.

**`overflow-x: clip` και όχι `hidden`.** Το `hidden` σε `html`/`body`
δημιουργεί scroll container και σπάει το `position: sticky` του navbar.

**Δίχτυ ασφαλείας reveal.** Τα `.reveal` ξεκινούν στο `opacity: 0`. Ένα
`<noscript>` block τα εμφανίζει αν το JavaScript δεν τρέξει, ώστε να μη
μείνει ποτέ αόρατο περιεχόμενο.

## GDPR

Καμία κλήση σε τρίτο δεν γίνεται πριν από ρητή συγκατάθεση. Τα προαιρετικά
πλαίσια ξεκινούν απενεργοποιημένα. Η επιλογή αποθηκεύεται τοπικά στο
`gpcode_consent_v1` και ανακαλείται από το footer.

Τα placeholders για **GA4, GTM, Microsoft Clarity, Google Ads, Meta Pixel και
LinkedIn Insight** βρίσκονται σχολιασμένα στο `js/cookie-consent.js`, μέσα
στη `loadTrackingScripts()`, χωρισμένα ανά κατηγορία συγκατάθεσης. Για να
ενεργοποιήσετε κάποιο: αφαιρέστε τα σχόλια, βάλτε το αναγνωριστικό σας,
**ενημερώστε το `cookies.html`** και τρέξτε ξανά `npm run build`.

Το meta tag επαλήθευσης του Google Search Console είναι σχολιασμένο στο
`<head>` κάθε σελίδας (`build/templates/layout.js`).

## Πριν το live — τι εκκρεμεί

Το site λειτουργεί πλήρως χωρίς τα παρακάτω, αλλά αυτά είναι που το κάνουν
αξιόπιστο σε νέο επισκέπτη. Κατά σειρά απόδοσης:

- [ ] **Branded email** (`info@gpcode.gr`) αντί για τη διεύθυνση Gmail →
      `data.contact.email`. Το πιο ορατό σημείο αμφισβήτησης στο site.
- [ ] **Κλειδί φόρμας**: λογαριασμός στο [web3forms.com](https://web3forms.com)
      → `data.contact.formAccessKey`. Μέχρι τότε η φόρμα εμφανίζει ευγενικό
      μήνυμα με το τηλέφωνο αντί να αποτυγχάνει σιωπηλά.
- [ ] **Πραγματική φωτογραφία** → `data.images.founder`
- [ ] **Χρόνια εμπειρίας** — ένας επιβεβαιωμένος αριθμός ξεκλειδώνει το
      «Χ χρόνια σε .NET» σε όλο το site. Χωρίς αυτόν δεν γράφεται τίποτα.
- [ ] **GitHub / LinkedIn** → `data.social` (γίνονται `Person.sameAs` και
      εμφανίζονται τα εικονίδια στο footer)
- [ ] **Οδός και ΤΚ** → `data.business.street` / `postalCode`. Ξεκλειδώνει
      αναβάθμιση του schema από `Organization` σε `ProfessionalService`.
- [ ] **Ημερομηνίες άρθρων** → `data.posts[].datePublished`, στις πραγματικές
      ημερομηνίες δημοσίευσης.
- [ ] **Εικόνα Open Graph**: η τρέχουσα είναι το σήμα σε βαθύ φόντο.
      Μια εκδοχή με κείμενο θα αποδίδει καλύτερα σε κοινοποιήσεις.

### Οι φωτογραφίες είναι διακοσμητικές

Οι πέντε εικόνες στο `images/` είναι εν μέρει δημιουργημένες με AI και
**δεν απεικονίζουν πραγματικά έργα, πελάτες ή τον ίδιο τον ιδιοκτήτη**. Τα
alt texts είναι γραμμένα ώστε να μην υπονοούν κάτι διαφορετικό («εννοιολογική
απεικόνιση…»), και η λεζάντα στο `about.html` το δηλώνει ρητά.

Αυτό είναι σκόπιμο: μια εικόνα ανθρώπου με λεζάντα που υπονοεί ότι είναι ο
developer θα ήταν ακριβώς το είδος ισχυρισμού που υπονομεύει το E-E-A-T.
Όταν υπάρξει πραγματική φωτογραφία, μπαίνει στο `data.images.founder`.

### Τι ΔΕΝ γράφουμε χωρίς πραγματικά δεδομένα

Έτος έναρξης · αριθμό πελατών ή έργων · ονόματα πελατών · μαρτυρίες ή
βαθμολογίες · «χρόνια εμπειρίας» · ωράριο · ολοκληρωμένες διασυνδέσεις με
συγκεκριμένο ERP ονομαστικά · οτιδήποτε υπονοεί προσωπικό.

Ο πίνακας `data.testimonials` είναι **σκόπιμα κενός**. Όσο μένει κενός, η
αρχική δείχνει τις γραπτές δεσμεύσεις. Μόλις προστεθεί πραγματική μαρτυρία
`{ quote, author, role, company }`, η ενότητα αλλάζει αυτόματα.

## Μετά την πρώτη δημοσίευση

1. Επαλήθευση ιδιοκτησίας στο Google Search Console και υποβολή του
   `sitemap.xml`
2. `https://pagespeed.web.dev` στην αρχική και σε μία σελίδα υπηρεσίας
3. [Rich Results Test](https://search.google.com/test/rich-results) σε μία
   σελίδα κάθε τύπου (αρχική, υπηρεσία, άρθρο, FAQ)
4. Επιβεβαίωση ότι το `404.html` σερβίρεται από τον διακομιστή σε άγνωστα URL
5. Redirect από `www` προς το κύριο domain (ή αντίστροφα) ώστε να ταιριάζει
   με τα canonical URLs
