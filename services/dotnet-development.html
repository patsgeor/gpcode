.NET Development

.NET Developer — ανάπτυξη σε ASP.NET Core & C#

Το .NET είναι η βασική μου πλατφόρμα. Από ένα Web API που εξυπηρετεί μια εφαρμογή Angular, μέχρι τη σταδιακή μετάβαση μιας εφαρμογής Web Forms που δουλεύει από το 2012 και δεν επιτρέπεται να σταματήσει.

Web APIs

REST APIs σε ASP.NET Core που καταναλώνει ένα SPA, μια εφαρμογή κινητού ή ένα τρίτο σύστημα.

Εφαρμογές MVC

Server-rendered εφαρμογές όταν δεν δικαιολογείται η πολυπλοκότητα ενός ξεχωριστού frontend.

Migration & εκσυγχρονισμός

Σταδιακή μετάβαση από .NET Framework, Web Forms ή WCF, χωρίς διακοπή της παραγωγής.

Background εργασίες

Προγραμματισμένες εργασίες, ουρές και επεξεργασία αρχείων που τρέχουν αξιόπιστα χωρίς επίβλεψη.

Πρόσβαση σε δεδομένα

EF Core ή Dapper, ανάλογα με το τι απαιτεί το κάθε κομμάτι της εφαρμογής.

Deployment

IIS, Linux ή Docker, με CI/CD ώστε η παράδοση να μην εξαρτάται από χειροκίνητα βήματα.

ASP.NET Core: Web API, MVC ή Blazor — πότε το καθένα

Και τα τρία είναι έγκυρες επιλογές. Η λάθος επιλογή δεν φαίνεται στην αρχή· φαίνεται στον έκτο μήνα.

Web API

Όταν το frontend είναι ξεχωριστό — Angular, React ή εφαρμογή κινητού — ή όταν τα δεδομένα πρέπει να είναι διαθέσιμα σε άλλα συστήματα. Η πιο ευέλικτη επιλογή, με κόστος ένα επιπλέον επίπεδο προς συντήρηση.

MVC / Razor Pages

Όταν η εφαρμογή είναι κυρίως φόρμες και πίνακες και δεν χρειάζεται πλούσια διαδραστικότητα. Λιγότερος κώδικας, ταχύτερη παράδοση, καλύτερο SEO όπου το περιεχόμενο είναι δημόσιο.

Blazor

Όταν η ομάδα ξέρει C# και δεν θέλει να συντηρεί ξεχωριστό stack JavaScript. Το Blazor Server θέλει σταθερή σύνδεση· το WebAssembly έχει μεγαλύτερο αρχικό φόρτωμα. Και τα δύο είναι πραγματικές παραχωρήσεις.

Αρχιτεκτονικά μοτίβα που χρησιμοποιώ

Χωρίς υπερμηχανική. Ο στόχος είναι κώδικας που μπορεί να διαβάσει και να επεκτείνει άλλος developer, όχι επίδειξη μοτίβων.

Διαχωρισμός σε επίπεδα

Ξεκάθαρα όρια ανάμεσα σε παρουσίαση, επιχειρησιακή λογική και πρόσβαση σε δεδομένα. Η επιχειρησιακή λογική δεν γνωρίζει τίποτα για HTTP ή SQL, οπότε μπορεί να ελεγχθεί χωρίς βάση δεδομένων.

Dependency injection

Ενσωματωμένο στο ASP.NET Core. Οι εξαρτήσεις δηλώνονται ρητά στον constructor, πράγμα που κάνει προφανές τι χρειάζεται κάθε κλάση και επιτρέπει αντικατάστασή τους στα tests.

EF Core ή Dapper

EF Core εκεί που το μοντέλο αλλάζει συχνά και η δουλειά είναι κυρίως CRUD: τα migrations και το change tracking γλιτώνουν πραγματικό χρόνο. Dapper εκεί που χρειάζεται ακριβής έλεγχος του SQL — τυπικά σε αναφορές και ερωτήματα μεγάλου όγκου. Τα δύο συνυπάρχουν άνετα στην ίδια εφαρμογή και δεν χρειάζεται να διαλέξετε ένα για πάντα.

Ασύγχρονος κώδικας παντού

Κάθε κλήση σε βάση ή δίκτυο είναι async. Αυτό δεν κάνει την εφαρμογή γρηγορότερη για έναν χρήστη — κάνει τον server ικανό να εξυπηρετήσει πολλούς ταυτόχρονα χωρίς να δεσμεύει threads σε αναμονή.

Ποιότητα κώδικα

  • Testing: unit tests στην επιχειρησιακή λογική, integration tests στα κρίσιμα σημεία. Όχι κάλυψη για την κάλυψη.
  • Logging: δομημένο logging ώστε ένα πρόβλημα στην παραγωγή να διαγιγνώσκεται από τα logs και όχι με εικασίες.
  • Error handling: κεντρική διαχείριση σφαλμάτων, με μηνύματα που δεν αποκαλύπτουν εσωτερικές λεπτομέρειες.
  • Configuration: ρυθμίσεις ανά περιβάλλον, με τα μυστικά εκτός repository.
  • Validation: έλεγχος εισόδου στα όρια του συστήματος, πάντα και στον server.

Συνδυάζεται με

  • Σχεδίαση REST APIs με τεκμηρίωση OpenAPI
  • SQL Server και PostgreSQL
  • Frontend σε Angular
  • Ολοκληρωμένες web εφαρμογές

Migration από .NET Framework και Web Forms

Οι περισσότερες ελληνικές επιχειρήσεις έχουν τουλάχιστον μία εφαρμογή που δουλεύει από το 2010 και κανείς δεν τολμά να την αγγίξει. Η μετάβαση είναι εφικτή, αλλά όχι πάντα συμφέρουσα.

  • Πρώτα η αξιολόγηση: αξίζει η μετάβαση ή αρκεί η συντήρηση;
  • Καταγραφή του τι θα σπάσει: WCF, System.Web, τρίτες βιβλιοθήκες
  • Σταδιακή προσέγγιση, με το παλιό και το νέο να συνυπάρχουν
  • Κάθε βήμα παραδίδεται λειτουργικό, χωρίς παύση της παραγωγής

Ερωτήσεις

Τεχνικές ερωτήσεις

Δουλεύετε σε legacy .NET Framework ή μόνο σε νέες εκδόσεις;

Και στα δύο. Νέα έργα ξεκινούν στην τρέχουσα LTS έκδοση του .NET. Παράλληλα αναλαμβάνω συντήρηση και σταδιακή μετάβαση εφαρμογών σε .NET Framework, συμπεριλαμβανομένων Web Forms και WCF, όπου η άμεση αντικατάσταση δεν είναι ρεαλιστική επιλογή.

Μπορείτε να ενταχθείτε σε υπάρχουσα ομάδα ως εξωτερικός developer;

Ναι. Δουλεύω με τα δικά σας εργαλεία και διαδικασίες: repository, branching strategy, code reviews και ό,τι χρησιμοποιεί ήδη η ομάδα. Η συνεργασία αυτή τιμολογείται ωριαία ή με πακέτο ωρών ανά μήνα.

Entity Framework ή Dapper — τι επιλέγετε και γιατί;

EF Core για μοντέλα που αλλάζουν συχνά και για CRUD, όπου τα migrations και το change tracking γλιτώνουν πραγματικό χρόνο. Dapper για αναφορές και ερωτήματα υψηλού όγκου, όπου χρειάζεται πλήρης έλεγχος του SQL. Τα δύο συνυπάρχουν άνετα στην ίδια εφαρμογή.

Τι παραδίδεται μετά την ολοκλήρωση; Έχω πρόσβαση στον πηγαίο κώδικα;

Παραδίδεται η εφαρμογή σε πλήρη λειτουργία, τεκμηρίωση χρήσης και των endpoints όπου υπάρχει API, και τα credentials για ό,τι είναι στο δικό σας όνομα — hosting, βάση δεδομένων, τυχόν λογαριασμό CI/CD. Ο πηγαίος κώδικας παραμένει στο gpcode και δεν περιλαμβάνεται εξ ορισμού στα παραδοτέα· πρόσβαση σε αυτόν δίνεται μόνο κατόπιν ξεχωριστής, ρητής έγγραφης συμφωνίας.

Γενικότερες ερωτήσεις για κόστος, χρόνο και άδεια χρήσης κώδικα υπάρχουν στη σελίδα συχνών ερωτήσεων.
